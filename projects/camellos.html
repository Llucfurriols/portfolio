Why it exists

Zero-friction party chaos

Camellos was born from a game my friends and I already loved playing. The problem was that everything was manual: we had to write everyone's names in the iPhone Notes app, keep track of the game ourselves, and argue over whose turn it was. It worked, but it was slow and clunky.

So I built Camellos to make the experience effortless. The app handles all the game logic, letting everyone focus on the fun instead of the admin. You can play by passing a single phone around the table or create an online room with a simple 4-digit code so everyone can join from their own device. No logins, no setup—just open the app and start playing.

The interesting engineering

Multiplayer without accounts

Online mode is host-authoritative over Supabase Realtime: the full game state is one JSONB document that only the host device writes; everyone else appends intentions (join, bid, vote) to an action queue. One writer, zero race conditions, no auth system — the room code is the security model.

Timers sync via a single end-timestamp; near-duplicate names ("Leo Messi" vs. "Messi") get caught by Levenshtein + Jaccard similarity.

Shipping gauntlet

Apple review, at speed

  • Custom post-clone script so Xcode Cloud could build Flutter at all
  • App Privacy labels, ATT, EU ad-consent (UMP), export-encryption declaration
  • Launch morning: fixing online rooms that survived after players left — and hand-drawing a Catalan flag, because iOS has no emoji for it
  • AdMob monetization with test ads in debug so review builds never fake clicks
